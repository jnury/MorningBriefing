IT Zero-day PaperCut exploité en production : 47 % des serveurs restent sans correctif

Deux failles (CVE-2026-81578 et CVE-2026-82078) permettent une exécution de code à distance pré-authentification sur les serveurs d'impression PaperCut NG/MF : un défaut de contrôle d'autorisation — PaperCut vérifie le droit d'afficher une page plutôt que celui d'exécuter l'action — combiné à un chargement de classes Java non sécurisé dans un utilitaire de base de données, aboutissant à du code arbitraire avec les privilèges SYSTEM. Huntress a confirmé l'exploitation active dans deux environnements clients, avec des commandes de reconnaissance rapides (whoami, ver, tasklist). Sur environ 2 500 installations suivies, 47 % tournent encore en version 23 ou antérieure, pour lesquelles aucun correctif n'existe. Les parcs concernés sont massivement des écoles, hôpitaux et administrations.

IT Manchester Airports Group : FulcrumSec revendique le vol de 86 Go et 8,7 millions de clients touchés

Le groupe d'extorsion FulcrumSec revendique le vol d'environ 86 Go de données chez Manchester Airports Group, qui exploite les aéroports de Manchester, London Stansted et East Midlands. Environ 8,7 millions de clients seraient concernés, la plupart pour leur seule adresse e-mail, mais près de 200 000 enregistrements contiendraient des dates de voyage à venir et des références de réservation rattachées à des identités. Les données comprennent horaires d'arrivée, terminal utilisé, montants payés et historique de dépenses. Selon FulcrumSec, l'accès a été obtenu via des identifiants d'API Iterable propres aux aéroports, exposés dans du JavaScript côté client. MAG affirme avoir contacté toutes les personnes affectées sans commenter les détails techniques. FulcrumSec, actif depuis 2025, exfiltre sans chiffrer.

IT TerminalFix : de faux CAPTCHA Cloudflare poussent les victimes vers PowerShell pour installer un backdoor

Microsoft documente TerminalFix, une variante de ClickFix qui, au lieu de la boîte Exécuter de Windows, dirige les visiteurs vers Windows Terminal ou PowerShell — ce qui augmente les chances qu'un script multi-lignes complexe s'exécute correctement. Le faux CAPTCHA Cloudflare fait copier-coller une commande qui télécharge une archive ZIP contenant un binaire légitime (LockScreenContentServer.exe) et une DLL piégée (dui70.dll) exploitée par sideloading. La DLL récupère les charges suivantes dissimulées dans des images PNG hébergées sur des domaines contrôlés. La persistance passe par des clés Run et des tâches planifiées. Le backdoor final, un client Python, tunnelise du trafic TCP arbitraire vers gitnow[.]dev:443 via WebSocket chiffré, offrant un accès proxy réseau persistant et permettant l'énumération d'Active Directory.

Les chercheurs de Socket ont identifié 19 modules malveillants répartis dans plusieurs extensions Chrome et Edge, au sein d'une campagne active depuis début 2024. IT Qubes OS : QSB-118 décrit une exécution de code arbitraire dans dom0 via qvm-copy-to-vm

Le bulletin de sécurité Qubes QSB-118 décrit une faille affectant toutes les versions de Qubes OS, le correctif étant publié pour Qubes 4.3. Si un utilisateur lance un qvm-copy-to-vm depuis dom0 vers une qube compromise, l'attaquant peut injecter une commande arbitraire dans dom0 et prendre le contrôle complet du système — soit exactement le scénario que l'architecture de compartimentation de Qubes cherche à empêcher. La cause racine tient à la fonction de remontée d'erreur : sanitize_remote_filename() supprime bien les caractères non-ASCII et les guillemets du nom de fichier distant, mais laisse passer les métacaractères shell, ensuite interprétés par l'appel system() servant à afficher la boîte de dialogue d'erreur.

IT Robot humanoïde Unitree G1 : root sans authentification par Bluetooth, et propagation possible entre robots

Deux vulnérabilités (CVE-2026-76639 et CVE-2026-76640) permettent d'obtenir un shell root non authentifié sur le robot humanoïde Unitree G1, vendu environ 20 000 dollars, à portée Bluetooth. La première tient à une validation insuffisante des noms de fichiers lors de l'ajout de « connaissances » au service de chatbot, ouvrant une traversée de répertoire et l'écriture de fichiers arbitraires. La seconde exploite une caractéristique Bluetooth acceptant les écritures d'appareils non appairés, combinée à une API cloud qui déchiffrait le blob d'amorçage pour n'importe quel compte Unitree gratuit, sans vérifier la propriété du robot. Un débordement de tampon (charge de 1 050 octets dans 500) donne alors le shell root. Un robot compromis peut en attaquer d'autres à portée.

IT AWS révèle son réseau « Resilient Network Graph » : 40 % d'efficacité énergétique en plus, gardés en marge

AWS déploie une architecture réseau à un seul niveau, plate et volontairement câblée de manière quasi aléatoire, baptisée Resilient Network Graph : elle améliore la résilience tout en réduisant les coûts, avec jusqu'à 40 % d'efficacité énergétique supplémentaire, et devient le standard des nouveaux datacenters. Pour router entre des milliers de chemins équivalents, Amazon a développé son propre protocole SIDR (Scalable Intent-Driven Routing), associé à Spraypoint pour l'acheminement. Tous les datacenters, y compris les nouvelles installations dédiées au machine learning, sont bâtis sur les mêmes spécifications. AWS reconnaît toutefois que ces gains sont conservés en marge plutôt que répercutés : les tarifs d'instances n'ont pas bougé depuis 2020, et AWS Interconnect introduit une facturation réseau forfaitaire.

IT Amazon ECS Express Mode : faire tourner un conteneur sans gérer ce qui l'entoure

The New Stack détaille Amazon ECS Express Mode, dont le principe tient dans la formule de l'article : « votre conteneur tourne ; tout ce qui l'entoure ne devrait pas être votre problème ». Le service vise à supprimer la charge opérationnelle qui accompagne habituellement une mise en production sur ECS — répartiteur de charge, réseau, mise à l'échelle, points d'entrée publics — en la prenant en charge automatiquement, pour laisser l'équipe se concentrer sur l'application conteneurisée elle-même. La démarche s'inscrit dans le mouvement plus large de simplification des plateformes de conteneurs, où les fournisseurs cloud cherchent à offrir une expérience proche du PaaS sans renoncer au modèle de conteneurs standard ni à l'écosystème existant.
