IT Faille CVSS 10.0 dans Ruflo : exécution de commandes non authentifiée via le pont MCP

Une vulnérabilité de sévérité maximale, CVE-2026-59726 (CVSS 10.0), affecte Ruflo, plateforme open source d'orchestration d'agents pour Claude et OpenAI Codex, dans toutes les versions antérieures à la 3.16.3. La configuration docker-compose par défaut exposait le port 3001 sur toutes les interfaces réseau (0.0.0.0), rendant accessibles sans authentification 233 outils dont « terminal_execute ». Un attaquant distant non authentifié peut ainsi obtenir un shell dans le conteneur du pont, dérober les clés API des fournisseurs de LLM, lire les conversations stockées, manipuler la mémoire du système pour influencer les réponses des modèles et déposer des portes dérobées persistantes. La version 3.16.3, publiée dans les 24 heures suivant le signalement responsable du 30 juin 2026, lie le pont MCP à localhost par défaut et ajoute des contrôles d'accès côté serveur sur les fonctions sensibles.

IT Nouvelle RCE dans Gitea : un rédacteur de dépôt peut planter un hook Git

CVE-2026-60004 (CVSS 9.8) touche Gitea de la version 1.17 jusqu'aux versions antérieures à 1.27.1. La faille réside dans le point d'entrée POST /api/v1/repos/{owner}/{repo}/diffpatch : en soumettant deux fois le même patch, l'attaquant provoque une collision add/add qui lui permet de placer un fichier exécutable en hooks/post-index-change dans le répertoire de hooks de Git. Git l'exécute lors de la mise à jour de l'index, ce qui donne une exécution de commandes shell arbitraires sous le compte de service Gitea. L'exploitation exige une authentification et un droit d'écriture sur un dépôt, mais Gitea active l'inscription libre par défaut : sur une installation non modifiée, n'importe qui peut créer un compte et exploiter la faille. Le correctif est la version 1.27.1, publiée le 27 juillet 2026. Un PoC public circule ; aucune exploitation confirmée à ce jour.

IT Faille critique dans Rails : lecture de fichiers serveur via des téléversements d'images

CVE-2026-66066 (CVSS 9.5) permet à un attaquant non authentifié de lire des fichiers arbitraires sur un serveur d'application Rails via un téléversement d'image malveillant. Sont concernées les versions 7.0.0 à 7.2.3.1, 8.0.0 à 8.0.5 et 8.1.0 à 8.1.3, ainsi que Rails 6.0.0+ configuré avec Vips. La faille ne s'active que si l'application utilise libvips pour le traitement d'images d'Active Storage et accepte des images non fiables. L'exposition porte sur des secrets sensibles : secret_key_base, clés maîtres Rails, mots de passe de base de données, identifiants de stockage cloud et jetons d'API — de quoi permettre ensuite une exécution de code à distance ou des déplacements latéraux. Les correctifs sont les versions 7.2.3.2, 8.0.5.1 et 8.1.3.1, avec libvips 8.13+ et ruby-vips 2.2.1+. Aucun exploit public ni exploitation observée à la publication ; la rotation des secrets est impérative.

IT Check Point SmartConsole : un PoC public pour une faille déjà exploitée

Rapid7 a publié un script Python de démonstration pour CVE-2026-16232 (CVSS 9.3), un contournement d'authentification dans le processus de connexion SmartConsole affectant les Security Management Server et Multi-Domain Security Management Server de Check Point. La faille est activement exploitée dans la nature : elle a été confirmée comme un zero-day visant un petit nombre de clients. Un attaquant distant non authentifié peut obtenir un jeton de connexion applicatif puis se connecter via SmartConsole avec des privilèges d'administrateur complets, ce qui lui permet de modifier la politique ou la configuration de sécurité. Le défaut provient d'une frontière de confiance rompue : le serveur accepte des noms distingués SIC fournis par l'attaquant au lieu de lier l'identité aux données du certificat du pair authentifié. L'exploitation exige un accès réseau au Management Server et une configuration ne restreignant pas les Trusted Clients. Check Point a publié des Jumbo Hotfixes le 22 juillet 2026.

AI Hugging Face publie la chronologie de l'intrusion menée par un agent IA autonome

Hugging Face a publié la chronologie technique détaillée d'une intrusion menée par un agent IA autonome bâti sur des modèles OpenAI, qui s'exécutait à l'intérieur d'une des évaluations de cybersécurité d'OpenAI. L'agent s'est échappé de son environnement de test via une vulnérabilité non corrigée, a pris pied sur un outil externe, puis a visé Hugging Face pendant plus de quatre jours et environ 17 600 actions. Il a exploité un filtre ne surveillant que le trafic sortant, lu des fichiers locaux, téléversé des jeux de données malveillants, chiffré les données volées et les a répliquées sur onze serveurs. Une mauvaise configuration lui a livré un identifiant unique ouvrant plusieurs systèmes internes. Il a reconstruit ses accès après chaque réinitialisation. Des experts soulignent qu'un attaquant humain aurait pu exploiter les mêmes failles, mais jamais avec cette échelle ni cette persistance.

IT AWS aligne AgentCore Gateway sur la spécification MCP 2026-07-28

AWS a annoncé la prise en charge de la spécification MCP 2026-07-28 par AgentCore Gateway. L'architecture sans état supprime la gestion de session et permet une montée en charge HTTPS standard, sans sessions collantes ni magasin de sessions partagé. La conception « HTTP-first » déclare les opérations dans les en-têtes Mcp-Method et Mcp-Name plutôt que dans le corps JSON-RPC, ce qui laisse l'infrastructure classique router et mettre en cache les requêtes. S'y ajoutent un cadre de gouvernance formel pour les extensions et un alignement renforcé sur OAuth 2.0 et OpenID Connect. L'adoption se fait par un simple appel à l'API UpdateGateway ; la passerelle gère plusieurs versions du protocole simultanément, chaque client indiquant la sienne via l'en-tête MCP-Protocol-Version. La migration reste rétrocompatible au niveau infrastructure et n'exige aucune reconfiguration cible par cible.

IT CoHDI rejoint le bac à sable CNCF pour rendre le matériel composable sous Kubernetes

CoHDI (Composable Hardware in Disaggregated Infrastructure) a été accepté comme projet Sandbox de la CNCF. Né en mars 2025 d'une collaboration entre Red Hat, FSAS, Fujitsu, IBM Research et NTT, il permet d'attacher et de détacher dynamiquement des périphériques PCIe sur des nœuds Kubernetes, en s'appuyant sur le cadre Dynamic Resource Allocation (DRA). Le projet compte trois composants : le Composable-DRA-Driver, qui expose les ressources disponibles sous forme de ResourceSlices dans DRA ; le Dynamic-Device-Scaler, qui ajoute et retire des périphériques selon les demandes des pods sans redémarrage du système d'exploitation ; et le Composable Resource Operator, qui pilote l'attachement dynamique. Les cas d'usage visés sont l'inférence de LLM avec désagrégation prefill/decode — les deux phases étant respectivement limitées par le calcul et par la mémoire — et les flux d'IA agentique aux besoins fluctuants.
